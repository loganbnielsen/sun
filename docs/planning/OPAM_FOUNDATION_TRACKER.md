## Readiness Definition

A package is OPAM-ready when:

- `dune build @install @runtest` passes in its own repo.
- `opam lint` passes on the generated `.opam`.
- `opam install . --deps-only --with-test` works from a clean switch.
- Public dependencies are declared in `dune-project`, not only present in the developer switch.
- README has one minimal install/use example and clearly names upstream packages it relies on.
- Tag exists for the version named in `dune-project` before publishing.
- Tests cover the package's real boundary, including at least one integration test when the package wraps an external service.
- Release metadata is set: license, homepage, bug reports, source, changelog, tag.

### Phase 5: Low-Cost Live AWS Smoke

Goal: prove `aws-eio` against real AWS without provisioning long-running infrastructure.

Rules:

- Use an explicit env gate, e.g. `AWS_EIO_LIVE=1`.
- Set an AWS Budget alert before running anything live.
- Prefer API calls with no persistent resource first.
- Any resource-creating test must tag resources and delete them in `Fun.protect`.
- Do not run EKS for the first AWS proof.

Order:

- [ ] STS `GetCallerIdentity` signed request smoke.
- [ ] S3 tiny-object smoke against one pre-created bucket and a `sun-live-test/` prefix: `PutObject`, `HeadObject`, `GetObject`, `DeleteObject`.
- [ ] S3 error-path smoke: `HeadObject` on a known-missing key.
- [ ] Optional DynamoDB smoke only if/when `dynamo-eio` exists.
- [ ] Full `sun cloud init --aws` dogfood only after the above is boring.

Minimal IAM shape for the first S3 lane:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "S3LiveTestObjectsOnly",
      "Effect": "Allow",
      "Action": ["s3:PutObject", "s3:GetObject", "s3:DeleteObject"],
      "Resource": "arn:aws:s3:::SUN_LIVE_TEST_BUCKET/sun-live-test/*"
    },
    {
      "Sid": "S3LiveTestListOnlyPrefix",
      "Effect": "Allow",
      "Action": "s3:ListBucket",
      "Resource": "arn:aws:s3:::SUN_LIVE_TEST_BUCKET",
      "Condition": {
        "StringLike": {
          "s3:prefix": "sun-live-test/*"
        }
      }
    }
  ]
}
```

Cost posture:

- STS first because it creates no resources and `GetCallerIdentity` needs no explicit permission.
- S3 object smoke should use one tiny object in a pre-created standard bucket and immediate cleanup.
- EKS is deliberately last; a cluster has hourly control-plane cost and is easy to forget running.
- AWS Budget alerts before first live run: start with low actual/forecast thresholds and no Budget Reports.

AWS source checks:

- STS `GetCallerIdentity`: AWS documents that no permissions are required.
- S3 pricing: AWS documents no minimum charge; storage, requests, retrieval, data transfer, and optional features are the cost components.
- AWS Budgets pricing: first two action-enabled budgets are free; later action-enabled budgets have a daily cost, and Budget Reports have per-report cost.
- `aws:RequestedRegion`: useful as a guard on requested endpoint region, but AWS documents it does not fully constrain cross-region impact.
