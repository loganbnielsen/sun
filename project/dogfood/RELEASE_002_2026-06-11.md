Pass. The published alpha.6 tarball works without a Sun source checkout or
`SUN_HOME`. The generated workspace builds, deploys locally, runs migrations,
serves HTTP requests, prints logs, emits a populated deployment plan, and emits

## Clean Install

Commands run from a temp directory outside the repo:

```bash
unset SUN_HOME
curl -fL -o sun-v0.1.0-alpha.6-linux-x86_64.tar.gz \
  https://github.com/loganbnielsen/sun/releases/download/v0.1.0-alpha.6/sun-v0.1.0-alpha.6-linux-x86_64.tar.gz
tar xzf sun-v0.1.0-alpha.6-linux-x86_64.tar.gz
export PATH="$PWD/sun-v0.1.0-alpha.6-linux-x86_64/bin:$PATH"
sun --help
sun new workspace alpha_release
cd alpha_release
eval $(opam env)
dune build
```

Outcome: pass.

Note: `dune` was not on the shell PATH until `eval $(opam env)` was loaded.
This is local developer environment state, not a release artifact issue.

## Static Product Verification

Deployment plan:

```bash
sun deploy --dry-run --emit-plan-to /tmp/alpha-release-plan.json
grep -q '"topics":' /tmp/alpha-release-plan.json
grep -q '"migrations":' /tmp/alpha-release-plan.json
```

Outcome: pass. The plan file includes `topics` and `migrations`.

GitOps output:

```bash
sun deploy --emit-to /tmp/alpha-release-gitops \
  --secret-backend external-secrets \
  --secret-store-ref alpha-store \
  --key-prefix /alpha/release
grep -R "kind: ExternalSecret" /tmp/alpha-release-gitops
! grep -R 'stringData:.*".\\+"' /tmp/alpha-release-gitops
```

Outcome: pass. GitOps output contains ExternalSecret resources and no populated
`stringData` values.

Finding: the original ticket text used stale flag `--secret-remote-prefix`.
The alpha.6 CLI correctly exposes `--key-prefix`, and the current README uses
the supported External Secrets flags. This ticket text mismatch is resolved by
this report; no product patch required.

## Local Product Loop

Commands:

```bash
sun dev up
sun up
sun migrate --table alpha_release_migrations
sun status
sun logs payments/charge_svc --no-follow --tail=50
```

Outcome: pass.

`sun dev up` reused the existing `sun-local` k3d cluster and successfully
upgraded/reconciled Redpanda, PostgreSQL, Loki, Grafana, and Prometheus.

First `sun up` built, pushed, and rolled out both services but exited nonzero
because port `8080` was held by an old `kubectl port-forward` for
`alpha-acme-payments/charge-svc`. After killing that stale port-forward and
rerunning `sun up`, the command completed successfully and established the
`alpha_release` port-forward.

Final status:

```text

Namespace: alpha-release-payments
charge-svc ... 1/1 Running
  -> http://localhost:8080 (charge-svc)
```

Logs command printed a Grafana Explore URL and current pod log output:

```text

sun-svc listening on :8080
```
