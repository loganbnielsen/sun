```
HTTP/1.1 500 Internal Server Error
{"error":"db unavailable"}
```

FAIL — the notifications endpoint returns 500. The charge worker presumably published a Kafka event, but the worker cannot connect to Postgres to persist notifications. The database migration (`sun migrate`) was not run as part of this dogfood path — the scaffold's "Next steps" output lists `sun migrate` but it appears after `sun up`, and a new user following the linear flow would hit this 500 before knowing to run it.

**Friction (high severity):** `GET /notifications` returns `{"error":"db unavailable"}` without running `sun migrate`. The scaffold next-steps hint lists `sun migrate --table alpha_acme_migrations` but it is the 4th step after `sun dev up`, `sun up`, and `sun status`. The ordering is correct but not obviously required. A new user will likely test their app before running migrations and see a confusing 500. Consider: (a) running `sun migrate` automatically as part of `sun up`, or (b) printing a prominent warning in `sun status` when unmigrated SQL files are detected.

## Step 6 — Verify Outputs

### Plan JSON

```json
{
  "topics": [],
  "migrations": [ "0001_notifications.sql" ],
  "secret_backend": "kubernetes-placeholder"
}
```

**topics: FAIL** — `"topics": []`. The workspace scaffold includes a Kafka worker (`notify_worker`) which presumably produces/consumes topics, but no topics appear in the plan JSON. Either (a) topic declarations are not parsed from `sun.toml`, or (b) the scaffold does not emit explicit topic declarations. A new user relying on the plan for IaC automation will not see any topics to pre-create.

**migrations: PASS** — `"0001_notifications.sql"` is correctly detected.

**secret_backend: PARTIAL** — The field is present with value `"kubernetes-placeholder"`. This does not reflect the `--secret-backend external-secrets` flag passed to `sun deploy`. The plan is written at `--dry-run` time before the `--emit-to` flags are applied. If a user runs `--dry-run --emit-plan-to` without `--secret-backend`, they get a misleading placeholder. The plan should either reflect the actual backend, or the `--secret_backend` flag should be composable with `--dry-run`.

### GitOps Output

**ExternalSecret: PASS** — Both manifests contain `kind: ExternalSecret` with `apiVersion: external-secrets.io/v1beta1`.

**stringData: PASS** — No `stringData` found in either file. Secrets are correctly replaced with ExternalSecret references.

ExternalSecret shape (per service):
```yaml
spec:
  refreshInterval: 1h
  secretStoreRef:
    name: alpha-store
    kind: ClusterSecretStore
  target:
    name: <service>-secrets
    creationPolicy: Owner
  data:
  - secretKey: POSTGRES_URL
    remoteRef:
      key: /alpha/acme/POSTGRES_URL
```

`--key-prefix /alpha/acme/` correctly prepended to secret key. `--secret-store-ref alpha-store` correctly set.

## Friction Log (Prioritised)

### High

1. **`GET /notifications` returns 500 before `sun migrate`** — A new user testing their scaffold immediately after `sun up` hits a database-unavailable error. No indication in `sun status` or `sun up` output that migrations are required. Consider auto-migration or a prominent unmigrated-schema warning.

2. **`"topics": []` in plan JSON** — Kafka topics are not surfaced in the deploy plan even when a Kafka worker exists. IaC tooling downstream of the plan will not know which topics to pre-create.

3. **`sun up` exits 0 when port-forward fails** — Service is deployed but unreachable. Exit code should be non-zero, or the warning should be elevated to a top-level error requiring `--force` to suppress.

### Medium

4. **`secret_backend: "kubernetes-placeholder"` in dry-run plan** — Dry-run plan does not reflect `--secret-backend` flag. Misleading for users who pipe the plan to IaC tooling.

5. **Version string is `dev`** — A shipped alpha binary must emit a real version string. Users cannot confirm which alpha they installed.

6. **Bundle vendor symlinks point to `/tmp/sun-alpha-bundle/framework`** — In a real release the path would be different (e.g. `~/.sun/`). The scaffold `linked` line prints the resolved symlink path; users will see a temp path that won't survive a reboot. This is a simulation artifact but highlights that the vendor resolution path is not yet release-hardened.

### Low

7. **Helm notes verbosity** — `sun dev up` prints multi-page Bitnami NOTES including upsell warnings. Should be filtered to sun-authored summary lines only.

8. **Docker push `Waiting` spam** — Multi-platform builds emit 20+ `Waiting` lines per push. Should be collapsed to a single progress line per service.

9. **`sun --version` does not warn about PATH collision** — System sun binary at `/home/lbendtly/.local/bin/sun` coexists silently with bundle binary. Could print a note if both are present.

10. **`loki-stack` deprecation warning** — Helm prints `WARNING: This chart is deprecated` on every `sun dev up`. Should be acknowledged in docs or suppressed.
