## Friction Log

### Friction 1: k3d proxy container in restart loop after host wakeup

**Step:** Pre-flight — `sun dev up`  
**Command:** `k3d cluster start sun-local`; then `kubectl get nodes`  
**Expected:** Cluster accessible immediately after starting.  
**Actual:** `k3d-sun-local-serverlb` container was in a restart loop (`Restarting (1)`). nginx could not resolve `k3d-sun-local-server-0` as an upstream host because the container started before the server container's network registration was complete. `docker restart k3d-sun-local-serverlb` fixed it.  
**Time lost:** ~2 minutes.  
**Workaround:** `docker restart k3d-sun-local-serverlb`.  
**Blocks two-minute claim?** no (cluster startup is outside the claim boundary).  
**Suggested fix:** `sun dev up` should detect a restarting proxy container and automatically restart it before attempting Helm installs.

### Friction 2: `sun up` fails with stale `_build/_tests` symlinks — `cp -rL` exits non-zero

**Step:** Step 4 — `sun up`  
**Command:** `sun up`  
**Expected:** Build context copied and Docker build starts.  
**Actual:** `cp -rL` tried to follow symlinks inside `framework/_build/_tests/` and `integrations/kafka/_build/_tests/` that point to paths under `sun/http/` and `sun/kafka/` — directories that no longer exist after the repo reorganization. `cp` exits 1 on unresolvable symlinks; `sun up` aborted with `error: failed to copy workspace for docker build context`.  
**Time lost:** ~5 minutes to diagnose.  
**Workaround:** Manually removed stale symlinks from `_build/_tests/` directories. Fixed by replacing `cp -rL` with `rsync -a --copy-links --exclude='_build'` in `cli/sun/bin/cmd_up.ml`.  
**Blocks two-minute claim?** yes  
**Suggested fix:** Replace `cp -rL` with `rsync -a --copy-links --exclude='_build' --exclude='.git'` in `cmd_up.ml`. This correctly excludes host build artifacts (which are never needed in Docker context) and avoids stale internal dune symlinks. **Fixed inline in this run.**

### Friction 3: Generated Dockerfile uses non-existent image tag `ocaml/opam:ubuntu-24.04-ocaml-5.4.1`

**Step:** Step 4 — `sun up` (Docker build stage)  
**Command:** `docker build` (invoked by `sun up`)  
**Expected:** Docker build resolves the base image from Docker Hub.  
**Actual:** `Error: ocaml/opam:ubuntu-24.04-ocaml-5.4.1: not found`. The opam Docker image registry uses `ubuntu-24.04-ocaml-5.4` (major.minor, no patch) not `ubuntu-24.04-ocaml-5.4.1`.  
**Time lost:** ~3 minutes to identify and verify the correct tag.  
**Workaround:** Changed template to `ubuntu-24.04-ocaml-5.4`. **Fixed inline in this run.**  
**Blocks two-minute claim?** yes  
**Suggested fix:** Update `tpl_dockerfile` in `cli/sun/lib/sun_cli_cmd_new.ml` to use `ocaml/opam:ubuntu-24.04-ocaml-5.4`. **Fixed inline in this run.**

### Friction 4: Docker COPY creates root-owned files; `opam` user cannot create `_build/`

**Step:** Step 4 — `sun up` (Docker build stage, `dune build` step)  
**Command:** `RUN opam exec -- dune build ...` inside Docker  
**Expected:** `dune build` compiles the workspace inside Docker.  
**Actual:** `Error: mkdir(_build): Permission denied`. `COPY . /workspace` creates files owned by `root`. The `opam` user (uid 1000 in the OCaml Docker image) cannot create the `_build` directory in `/workspace`.  
**Time lost:** ~2 minutes.  
**Workaround:** Changed `COPY . /workspace` to `COPY --chown=opam:opam . /workspace`. **Fixed inline in this run.**  
**Blocks two-minute claim?** yes

---

### Friction 5: Dockerfile `opam install` missing TLS system packages (`libgmp-dev`, `pkg-config`) and opam packages (`tls-eio`, `x509`)

**Step:** Step 4 — `sun up` (Docker build stage, `opam install` step)  
**Command:** `RUN opam install -y ... tls-eio x509 domain-name` inside Docker  
**Expected:** opam resolves all packages including TLS dependencies.  
**Actual:** `[ERROR] Package conflict! Missing dependency: x509 → mirage-crypto-pk → conf-gmp-powm-sec → libgmp-dev`. The `x509` package (added by AUDIT-029 TLS schema registry support) requires `libgmp-dev` and `pkg-config` as system packages, but the Dockerfile `apt-get` step did not include them. Additionally, `tls-eio`, `x509`, `domain-name` were not in the Dockerfile template's `opam install` list.  
**Time lost:** ~3 minutes.  
**Workaround:** Added `libgmp-dev pkg-config` to `apt-get install` and `tls-eio x509 domain-name` to `opam install` in `tpl_dockerfile` in `sun_cli_cmd_new.ml`. **Fixed inline in this run.**  
**Blocks two-minute claim?** yes

## Two-minute claim evaluation

With pre-warmed Docker layer cache (after the first `sun up` which builds the opam environment), subsequent `sun up` runs would skip all `apt-get` and `opam install` layers (cached). The bottleneck for repeat runs is the `dune build` step inside Docker, which takes ~5-10 seconds on a pre-built workspace. The two-minute claim for repeat deploys is realistic once the image cache is warm. The first-run claim requires noting that initial Docker layer population takes several minutes.
