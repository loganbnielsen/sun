## Findings and fixes

### README.md

#### FINDING-001 — HIGH — GitOps security note describes manual remediation for a problem that is now solved

**What was wrong:** The `sun deploy --emit-to` security note said "The generated YAML includes `Secret` resources with plain-text values in `stringData`" and told users to manually replace `stringData` values. FEAT-019 merged `--secret-backend external-secrets` which emits `ExternalSecret` CRDs instead, and the default mode now emits redacted placeholders (not plain-text values).

**What was fixed:** Replaced the note with a description of `--secret-backend external-secrets`, `--secret-store-ref`, and `--secret-store-kind` flags. Explains that the default output is redacted. Provides a concrete usage example.

#### FINDING-002 — MEDIUM — `sun logs` section missing Grafana URL behavior (FEAT-023)

**What was wrong:** `sun logs` now prints a copyable Grafana Explore URL before streaming kubectl logs (via `--grafana-base-url`, default `http://localhost:3000`). The Day-2 streaming logs section described the Loki/Grafana pointer as a manual workaround ("open Grafana at http://localhost:3000") without mentioning that `sun logs` itself prints the URL.

**What was fixed:** Added a paragraph and example showing `--grafana-base-url`. Updated the Note to clarify that the Grafana URL is printed by `sun logs` before streaming starts.

#### FINDING-003 — MEDIUM — `sun cloud init` Prerequisites lists `SUN_HOME` as a general requirement

**What was wrong:** The Cloud Infrastructure section listed `SUN_HOME` as a prerequisite for `sun cloud init` without qualifying that it's only needed for source checkouts. Tarball users don't need it because Terraform modules are bundled in the tarball.

**What was fixed:** Replaced the bullet with a conditional: "If you are using a source checkout instead of the tarball, set `SUN_HOME` to the repo root." Added a note that tarball bundle resolves modules automatically.

### docs/guides/TUTORIAL.md

#### FINDING-004 — HIGH — Install path uses single-binary download, not tarball

**What was wrong:** The TUTORIAL used `curl -sSL .../sun-linux-x86_64 -o ~/.local/bin/sun && chmod +x ...` — a single binary download format. The README's primary install path (established in FEAT-022) uses the tarball bundle which also ships `framework/` and `integrations/` source. The single-binary path leaves users without the framework source needed for `sun new workspace` to create vendor symlinks.

**What was fixed:** Updated the install block to match the README's tarball install path. Kept the build-from-source callout and added `git clone + SUN_HOME` there (where it belongs).

#### FINDING-005 — HIGH — Vendor links callout says "when using the downloaded binary, set SUN_HOME"

**What was wrong:** The Part 2 callout told users with the "downloaded binary" to set `SUN_HOME` — which is the opposite of the tarball's design intent (no SUN_HOME needed when using the bundle).

**What was fixed:** Split the callout into two cases: tarball install (no SUN_HOME, automatic) vs source checkout (SUN_HOME required). Made the source-checkout fallback step-by-step instructions appear only for that case.

### Generated workspace README (`cli/sun/lib/sun_cli_cmd_new.ml` — `tpl_readme`)

#### FINDING-006 — MEDIUM — Vendor links section presents SUN_HOME as the primary mechanism

**What was wrong:** The generated README opened with "`vendor/framework` and `vendor/integrations` must be symlinked to a Sun source checkout. They are created automatically when `SUN_HOME` is set during `sun new workspace`." This made `SUN_HOME` look like the universal requirement, which contradicts the tarball approach.

**What was fixed:** Reworded to explain that tarball users get automatic setup (no SUN_HOME), and source checkout users need `SUN_HOME`. The fallback symlink repair commands are retained for the "after cloning" case.

#### FINDING-007 — MEDIUM — `sun migrate --table {{name}}_migrations` implies per-workspace table is required

**What was wrong:** The deploy section showed `sun migrate --table {{name}}_migrations` — suggesting users must pass a per-workspace table name. The default `sun_schema_migrations` table works for all workspaces sharing a Postgres instance. Showing the flag without context made it look mandatory.

**What was fixed:** Changed to plain `sun migrate` without the `--table` flag. The `--table` flag remains available for advanced users who want isolation.
