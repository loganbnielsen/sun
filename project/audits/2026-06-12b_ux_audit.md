## Findings

### EXP-016 — `sun cloud deploy` tutorial omits required `--registry` flag

* **Stage:** 5 First Deploy (hosted mode) / 7 Day-2 Operations
* **Gate:** Docs
* **Severity:** High
* **Status:** Open
* **Description:** `docs/guides/TUTORIAL.md` (and the "Hosted control-plane release history" section added by CLOUD-004) shows `sun cloud deploy --environment production` without a `--registry` or `CLOUD_REGISTRY` env var. After CLOUD-005, `sun cloud deploy` requires `--registry <URL>` or `CLOUD_REGISTRY` to be set for any non-dry-run invocation. Following the documented command produces `error: --registry or CLOUD_REGISTRY required for hosted deploy` and exits 1.
* **Impact:** A user enabling the hosted deploy path cannot get past the first example command without consulting the CLI help text. This breaks the "follow the docs" promise for the hosted lane.
* **Remediation:** Update the tutorial's `sun cloud deploy` example to include `--registry` (or explain that `CLOUD_REGISTRY` can be set in the environment). Add a brief note explaining what the registry URL refers to (the container registry where built images are pushed). Also update `README.md` Status row "Sun-hosted executor" from "Experimental mock boundary" to reflect the real build-and-push pipeline introduced by CLOUD-005.
