### [EXP-012] — Stage 1/2: Missing `libpq-dev` prerequisite in TUTORIAL.md
* **Stage:** 1 Installation → 2 Project Creation
* **Gate:** Docs
* **Severity:** Medium
* **Description:** TUTORIAL.md Prerequisites (line 27) lists only `librdkafka-dev`. The generated workspace includes `caqti-driver-postgresql` in its `bin/dune` files, which requires `libpq-dev` at build time and `libpq5` at runtime. The README also omits `libpq-dev`. ### [EXP-013] — Stage 2: `vendor/` symlinks and `SUN_HOME` not documented for users
* **Stage:** 2 Project Creation
* **Gate:** Docs
* **Severity:** High
* **Description:** `sun new workspace` creates `vendor/framework` and `vendor/integrations` as symlinks pointing into the Sun checkout (inferred from the binary path via `/proc/self/exe`). Neither README nor TUTORIAL.md mentions these symlinks or the `SUN_HOME` fallback. If `infer_sun_home()` fails (e.g., binary was copied rather than symlinked, or `SUN_HOME` is not set), the workspace is created without `vendor/` links and `dune build` fails with "Library not found: sun_svc". The CLI prints a NOTE about this only when the problem has already occurred. There is no pre-flight check or user-facing doc.
* **Impact:** An engineer who installs `sun` by copying the binary (as TUTORIAL.md suggests: `cp _build/default/cli/sun/bin/main.exe /usr/local/bin/sun`) and then runs `sun new workspace` will get a workspace that silently omits the vendor links. `dune build` fails with a cryptic "Library not found" error. There is no doc path to diagnose or fix this.
* **Remediation:** (a) Add a "How vendor links work" note to TUTORIAL.md Part 2 explaining that the generated workspace links Sun framework source from the checkout, and that `SUN_HOME=/path/to/sun/checkout` can be set if the binary is not inside the checkout. (b) Update README Quickstart to use `ln -sf` (symlink) rather than `cp` for the sun binary installation, so the binary stays inside the checkout and `infer_sun_home()` succeeds. (c) Consider making the `NOTE:` output a clear `error:` with `exit 1` rather than continuing silently, so engineers are not surprised by the subsequent `dune build` failure.
