## Findings

### AUDIT-036 — Sun `dune-project` missing TLS package dependencies

* **Category:** DX / Framework Boundary
* **Severity:** Medium
* **Location:** `dune-project` (lines 8–22)
* **Status:** Open
* **Description:** The Sun monorepo's `dune-project` declares `(generate_opam_files true)` and lists package dependencies under `(package (name sun) ...)`. After AUDIT-029 added `tls-eio`, `x509`, `domain-name`, and `ptime` as library dependencies of `kafka-eio-service`, these packages were not added to the `(package ... (depends ...))` stanza in `dune-project`. The generated `sun.opam` file (produced by `dune build @all`) will be missing these dependencies.
* **Impact:** Anyone installing Sun from source via `opam install . --deps-only` will not have `tls-eio`, `x509`, `domain-name`, and `ptime` installed. `dune build` will fail with `Library "x509" not found` after a fresh `opam install . --deps-only`. The Sun CI workflow (if it uses `opam install . --deps-only`) will fail silently or error.
* **Remediation:** Add `tls-eio`, `x509`, `domain-name`, and `ptime` to the `(depends ...)` stanza in `dune-project`:
  ```
  tls-eio
  x509
  domain-name
  ptime
  ```
