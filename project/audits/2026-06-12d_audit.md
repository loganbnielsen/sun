## Findings

### AUDIT-029 — Schema registry HTTP client does not support TLS

* **Category:** Security / Data Integrity
* **Severity:** High
* **Location:** `integrations/kafka/kafka-eio-service/lib/kafka_service.ml`, `parse_base_url` (Lines 38–42)
* **Description:** `parse_base_url` explicitly rejects `https://` URLs with `failwith "kafka_service: HTTPS schema registry not yet supported"`. No TLS connection to a schema registry is possible. AUDIT-013 changed this from a confusing DNS error to a clear failure message, but full TLS support was never implemented. The audit checklist requires that HTTPS URLs are handled because all managed Kafka cloud offerings use HTTPS for their schema registry.
* **Impact:** Sun cannot be used with any managed Kafka offering (Confluent Cloud, MSK, Redpanda Cloud) that requires HTTPS for schema registry access. This blocks every production cloud deployment that uses schema validation.
* **Remediation:** Implement TLS support in the schema registry HTTP client. Use `cohttp-eio`'s TLS support (or `tls-eio`) to open an HTTPS connection when the URL starts with `https://`. `parse_base_url` should return `(host, port, use_tls)` and `http_do_once` should open a TLS socket when `use_tls = true`. Test with a self-signed cert and with a public endpoint.
