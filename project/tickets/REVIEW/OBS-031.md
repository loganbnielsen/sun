sun logs/sun status have no default path to durable/external Loki and Prometheus

**Depends on:** None.

## Problem

`Sun_cli_status.probe_url` (`cli/sun/lib/sun_cli_status.ml`) and `sun logs`'s
Loki query path (`cli/sun/bin/cmd_logs.ml`) only resolve a real Loki/
Prometheus URL for the `Local` backend's hardcoded `localhost` default, or
when the operator passes an explicit `--loki-base-url`/`--prometheus-base-url`
flag by hand. For `self_hosted_durable` or `external`, both commands report
"not checked" / fall straight through to ephemeral `kubectl logs` unless the
operator already knows to set up their own access path (e.g. `kubectl
port-forward` into the cluster) and pass the URL flag every time.

`sun dev up` (`cli/sun/bin/cmd_dev.ml`) only wires port-forwards for `local`;
there's no equivalent convenience for a real (`self_hosted_durable`) cluster.

Net effect: the durable Loki/Thanos infra provisioned by
`platform/infra/aws`/`platform/infra/base` (S3-backed Loki, Thanos) has no
CLI-side default path to it at all. An operator on a real deployment target
gets silently downgraded to `kubectl logs`/"not checked" with no indication
that's happening unless they already know the flags exist.

## Goal

`sun logs`/`sun status` against a `self_hosted_durable`/`external` target say
clearly *why* they're not checking and *what* to pass to make it work,
instead of silently falling back to `kubectl logs`/"not checked".

## Decision

No new externally-reachable endpoints. Operator continues to manage their own
`kubectl port-forward`; Loki/Prometheus stay off any Ingress by default for
`self_hosted_durable`. The fix is entirely in the CLI's messaging: when
`sun logs`/`sun status` would otherwise silently fall back to `kubectl logs`/
"not checked" for `self_hosted_durable`/`external`, say so explicitly and
print the exact `kubectl port-forward` command plus the flag
(`--loki-base-url`/`--prometheus-base-url`) needed to point the CLI at it.

Distinguish the two messages — they're operationally different failures:

- **No URL configured**: no `--loki-base-url`/`--prometheus-base-url` flag
  and the backend isn't `Local` → "not checked, here's how to point me at
  it" (the `kubectl port-forward` + flag message above).
- **URL configured but the query failed**: a flag (or a future default) was
  given and the request itself errored (connection refused, timeout,
  non-2xx) → a distinct "couldn't reach `<url>`: `<error>`" message, not the
  same "not checked" text. Conflating the two hides a real outage or a wrong
  URL behind what looks like the normal unconfigured case.
