sun status: a declared service with zero pods should report degraded, not healthy; add a regression test for the OBS-022 existence check

**Depends on:** None.

## Problem

Two related gaps in OBS-022's review:

1. `Sun_cli_rollout_diagnosis.format_service_diagnosis` returns `None`
   (vacuously "no unhealthy pods") when the pod list is empty.
   `rollup_domain_status ~ns_exists:true [None]` then reports `healthy`.
   So even after OBS-022 rejects a truly *undeclared* service, a
   *declared* one still lies if its Deployment is missing, scaled to
   zero, has a broken selector, or was simply never created — the
   namespace exists, but there's nothing running, and `sun status`
   still says healthy. This defeats the whole point of the diagnosis:
   the existing comment on its call site literally says "works even
   when the app never started ... so it's printed unconditionally" —
   an empty pod list *is* "never started."
2. OBS-022 (PR #81) shipped with no regression test — `test_status.ml`
   is unchanged, and the fix lives entirely in `cmd_status.ml` as an
   inline `List.exists` check with nothing pulled out to test.

## Goal

An empty pod list for a namespace that exists is treated as a real
diagnostic finding, not silence — but only when kubectl actually
confirmed there are zero pods, not when the kubectl call itself failed
(a transient failure should stay silent, as today, not falsely report
"no pods"). The service-existence check OBS-022 added gets a real
regression test.

## Acceptance criteria

- `Sun_cli_rollout_diagnosis.fetch_pod_statuses` distinguishes "kubectl
  succeeded, confirmed zero pods" from "kubectl call failed" (e.g. by
  returning `pod_status list option`, `None` on failure) so callers don't
  conflate the two.
- `format_service_diagnosis`/`diagnose_service_live` treat a *confirmed*
  empty pod list as a diagnosis (e.g. "`<service_name>` rollout failed ...
  No pods found for this service."), not `None`. A failed kubectl call
  still yields `None` (silent), unchanged from today.
- Existing `format_service_diagnosis` tests (healthy pods, ImagePullBackOff)
  are unaffected; a new test covers the empty-pod-list case explicitly.
- The service-existence decision OBS-022 added is extracted into a small
  pure helper (e.g. in `Sun_cli_status`) taking the set of declared k8s
  names and the requested one, returning a bool — and gets a direct unit
  test (declared name → true, undeclared name → false).
- `sun status <domain>/<service>` for a declared-but-not-actually-running
  service now reports `DEGRADED`, not `healthy`.
