Domain overview Grafana dashboard

**Depends on:** None.

## Problem

`docs/architecture/observability-design.md`'s Dashboard Shape section specs
five dashboards. OBS-011 built two (`docs/deployment/
observability-backends.md`): a workspace-wide overview and a
`$domain`/`$service`-parameterized service template. There is no dashboard
scoped to *one domain across its services* — today's choice is workspace-wide
(every domain at once) or single-service (the service template with
`$service` pinned). A domain-level incident (e.g. every `payments` service
degrading at once) has no dedicated view between those two.

## Goal

A third dashboard, scoped by a `$domain` template variable only (no
`$service`), showing per-service breakdowns of the same signals the
workspace overview aggregates (request rate, 5xx rate, scrape-target
health) — one row or panel group per service in that domain, plus a
domain-scoped Loki logs panel matching the service template's existing
pattern.

## Non-goal

**A dedicated service-only logs dashboard is explicitly not being built.**
The existing service template (OBS-011) already embeds a Loki logs panel
filtered to the selected `$domain`/`$service`, which covers this use case in
practice. Building a second, logs-only dashboard would duplicate that panel
with no distinct capability — if a real workflow gap shows up later that the
service template's embedded panel can't cover, ticket that gap specifically
rather than building speculative parallel dashboards now.

## Remediation

1. Add a new dashboard JSON (mirroring the service template's structure:
   `docs/architecture/observability-design.md` + OBS-011's implementation
   for the sidecar ConfigMap-loading convention) parameterized by `$domain`
   only.
2. Wire it into the same `grafana.sidecar.dashboards` ConfigMap-loading path
   `platform/infra/base/main.tf`'s `helm_release.loki` already uses for the
   other two dashboards.
3. Validate dashboard JSON well-formedness and Terraform/Helm wiring the
   same way OBS-011 did (`terraform validate`, values checked against `helm
   show values`) — live-Grafana rendering verification stays out of scope
   here, covered by `DOGFOOD-010` (needs real cluster access).

## Acceptance criteria

- A new Grafana dashboard, parameterized by `$domain` (populated from live
  Prometheus label values, not a list Sun maintains), shows per-service
  request rate / 5xx rate / scrape health for every service in that domain,
  plus a domain-scoped Loki logs panel.
- `terraform validate` and the chart-values check both pass.
