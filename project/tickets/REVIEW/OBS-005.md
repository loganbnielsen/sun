Observability persistence: pluggable backend interface

**Depends on:** OBS-004.

## Problem

Loki and Prometheus in `platform/infra/base` only support local/PVC storage
(`loki_persistent_storage`, `prometheus_persistent_storage` — both plain
booleans). There is no durable option, and no way to point either at
infrastructure outside the cluster.

This is a framework-level gap, not a hosted-product one: Sun is a self-hosted
factory that users deploy into their own infrastructure (see
`docs/planning/ROADMAP.md`'s Product Boundary — Sun decides the default
infrastructure shape, users bring the account it runs in). A future "Sun
Cloud" hosted lane may eventually operate this on someone's behalf, but
`docs/planning/ROADMAP.md` already records that a hosted executor was spiked
and then explicitly removed (2026-06-22) for getting ahead of a
not-yet-stable self-hosted contract. Same lesson applies here: design the
framework interface now, let a hosted product plug into it later.

## Goal

A per-target config surface in `platform/infra/base` selects one of three
observability backend profiles. No vendor is chosen by Sun at this layer —
that's a user (or, later, Sun Cloud) decision.

| Profile | Behavior |
|---|---|
| `local` (default) | Today's behavior: in-cluster Loki/Prometheus, optional PVC. No change required beyond naming it. |
| `external` | Sun configures promtail (`clients.url`) and Prometheus (`remote_write`) to point at a **user-supplied** endpoint + credentials. Loki + Grafana are skipped entirely (promtail ships lines directly, no local server needed). Prometheus itself is **not** skipped — it's pull-based (it scrapes each service's `/metrics`), so it still has to run to produce the samples `remote_write` forwards; only its local storage becomes a short-retention buffer instead of the durable store. |
| `self_managed_durable` | Object-storage-backed Loki, durable Prometheus storage. **Interface placeholder only in this ticket** — OBS-006 (logs) and OBS-007 (metrics) each own their half of the actual implementation. This ticket just needs the profile to exist and be selectable. |

Vendor selection and Sun Cloud economics are explicitly **out of scope**.
`external` is deliberately generic (endpoint + credentials, no vendor-specific
config) — that genericness is what lets a future Sun Cloud provision the
endpoint and inject credentials on a user's behalf without the framework
layer ever needing to know the difference.

## Acceptance criteria

- A single Terraform variable in `platform/infra/base` (e.g.
  `observability_backend = "local" | "external" | "self_managed_durable"`)
  selects the profile; `local` remains the default so existing targets are
  unaffected.
- `external` profile: promtail and Prometheus `remote_write` point at
  user-supplied endpoint/credential variables; local Loki + Grafana Helm
  releases are skipped when this profile is active (Prometheus still runs,
  scrape-and-forward only, minimal local retention).
- `self_managed_durable` profile is defined (variable accepts the value,
  documented as "implemented by OBS-006/OBS-007") but does not need a working
  backend in this ticket.
- `sun logs`/`sun status` are unaffected by backend choice for the `local`
  and `self_managed_durable` profiles (same in-cluster Loki, just a different
  storage backend underneath).
- **Known follow-up, not required here:** `sun logs`'s Loki client
  (`Sun_cli_loki`, built in OBS-002) sends unauthenticated queries. A real
  `external` target (e.g. a managed Loki-as-a-service endpoint) will likely
  require an API key/auth header on queries — `sun logs` querying an
  `external`-profile target may just fail through to the kubectl fallback
  until that's added. Call this out in the PR; file a follow-up ticket if it
  isn't fixed here.
- Documented: what each profile requires (credentials, network path) and how
  to switch a target between profiles.
- **Scope:** AWS only (`platform/infra/aws` + `platform/infra/base`). GCP is a
  deliberate gap for now, not a missing requirement — leave a clear TODO
  rather than stub in unverified GCS wiring.
- **Verification:** `dune build`/`terraform validate` only — no live
  cluster/AWS smoke test in this pass.
