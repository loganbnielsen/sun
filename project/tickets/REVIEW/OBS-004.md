Ensure promtail captures Kubernetes pod stdout/stderr

**Depends on:** None.

## Problem

App-pushed Loki logs miss the most important early failures: bad entrypoint,
segfault before logging init, OOMKilled, CrashLoopBackOff, and image startup
errors. Those show up in Kubernetes pod logs/events, not in app logging.

## Goal

Make the Sun platform Loki install scrape pod stdout/stderr through promtail so
runtime logs include failures before application code initializes.

## Acceptance criteria

- The base platform installs promtail or equivalent pod log collection by
  default with Loki.
- Pod logs include stable labels for namespace, pod, container, app/service, and
  Sun target where available.
- A pod that writes to stdout before exiting is queryable in Loki.
- A crash-looping pod's previous container log is discoverable through either
  Loki or the `sun logs` Kubernetes fallback.
- Live smoke criteria include a pod-log ingestion check, not only Loki `/ready`.
