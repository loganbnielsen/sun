Warn when migrations are pending before the app is exercised.

**Depends on:** None.

**Problem:** After `sun up`, `GET /notifications` returns 500 because database
migrations have not been run. `sun migrate` is mentioned in the scaffold
next-steps output but appears as step 4 after three other commands. New users
exercise the app before running migrations and see a confusing 500.

**Remediation:**

1. In `sun status`, scan `db/migrations/*.sql` and compare against a
   `.sun/applied_migrations` marker file (or a configurable table). If
   unapplied SQL files exist, print a prominent warning:
   `⚠ Pending migrations — run: sun migrate --table <workspace>_migrations`
2. As a lower-complexity alternative: print the same warning at the end of
   `sun up` output when migration files are present but the migrate command
   has not been run in this session.
3. Add a test that verifies the warning appears when migration files exist.

**Acceptance criteria:**

- `sun status` (or `sun up`) prints a pending-migrations warning when
  `db/migrations/*.sql` files exist and migrations have not been applied.
- Warning does not appear when no migration files exist.
- Warning does not block the command — it is informational.
