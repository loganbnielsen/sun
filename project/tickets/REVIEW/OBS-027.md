sun logs is deployment-only; scheduled functions are second-class

**Depends on:** None.

## Problem

`cmd_logs.ml` checks `kubectl get deployment <k8s_name>` to confirm the
target exists, and tails via `kubectl logs deployment/<k8s_name>`. A
scheduled function (`Fn`, CronJob-backed) has no Deployment at all — `sun
logs <domain>/<fn-service>` can't find it and can't tail it, even though
OBS-008's label taxonomy and OBS-023's dashboard variables already treat
`Fn` as a first-class primitive with its own Loki logs.

Flagged during review of OBS-026 (`sun status`'s `Fn`-awareness fix);
noted as real but not blocking, since `sun status`'s fix was scoped
separately from `sun logs`.

## Goal

`sun logs <domain>/<fn-service>` works for scheduled functions the same
way it works for `Svc`/`Worker`.

## Decision

For snapshots, `sun logs --no-follow` queries Loki by Sun's labels first.
If Loki is unavailable or empty, `Fn` falls back to `kubectl logs -l
app=<k8s_name> --all-containers=true`; `Svc`/`Worker` keep
`kubectl logs deployment/<k8s_name>`. For live follow, `Fn` uses the same
label selector rather than inventing a run-history UI.
