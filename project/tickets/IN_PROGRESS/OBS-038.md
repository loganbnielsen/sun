Deploy/release timeline Grafana dashboard

**Depends on:** OBS-037.

## Problem

`docs/architecture/observability-design.md`'s Dashboard Shape section specs
a "deploy/release timeline" dashboard — the last of the five specced
dashboards with no implementation at all (`OBS-011` built two; `OBS-036`
adds a third). It has a real prerequisite: nothing emits a queryable release
event today. `OBS-037` closes that gap by having `sun deploy` push a
structured Loki log line per successful deploy.

## Goal

A Grafana dashboard (or a panel added to the existing workspace-overview /
domain dashboards — pick whichever fits the design doc's intent once
`OBS-037`'s log line shape is final) that shows deploy/release events over
time, filterable by `$domain`/`$service`, using `OBS-037`'s log lines as the
data source (a Loki logs panel or table querying on the `event=deploy`
field, matching `workspace`/`env`/`domain`/`service`/`primitive`/`release`
labels).

## Remediation

1. Once `OBS-037` lands, confirm the log line's exact field/label shape.
2. Build the dashboard panel(s) querying Loki for that event type, wired
   into the same `grafana.sidecar.dashboards` ConfigMap-loading path
   `platform/infra/base/main.tf`'s `helm_release.loki` already uses.
3. Validate the same way `OBS-011`/`OBS-036` did (`terraform validate`,
   `helm show values` check) — live-Grafana rendering verification stays
   out of scope, covered by `DOGFOOD-010`.

## Acceptance criteria

- A Grafana view shows deploy/release events as discrete markers or rows
  over time, scoped by `$domain`/`$service`, sourced from `OBS-037`'s log
  lines.
- `terraform validate` and the chart-values check both pass.

## Non-goal

Grafana annotations rendering deploy events as native timeline markers on
existing time-series panels — noted as a possible richer follow-up in
`OBS-037`'s Decision section, not built here.
