# SEC-002: Unquoted shell variables in kubectl commands (rollback, logs, up)

**Depends on:** None.

## Summary

Several CLI commands pass user-controlled or filesystem-derived identifiers into
`Sys.command` shell strings without `Filename.quote`. This is inconsistent with the
established quoting pattern already used in `cmd_up.ml`'s `start_port_forward` and in
`sun_cli_manifest.ml`'s `apply_live`.

A workspace directory whose name contains shell metacharacters (e.g. a name with `;`,
`$`, or `` ` ``) would cause command injection when `sun rollback` or `sun logs` runs.
For `sun logs`, the service name is supplied directly as a CLI argument, making this
exploitable by any caller who controls that argument.

## Affected code

### `cli/sun/bin/cmd_rollback.ml` — lines 30, 42

```ocaml
let undo_cmd = Printf.sprintf
  "kubectl rollout undo deployment/%s -n %s" k8s_name ns in
...
let status_cmd = Printf.sprintf
  "kubectl rollout status deployment/%s -n %s" k8s_name ns in
```

`k8s_name` and `ns` are not quoted.

### `cli/sun/bin/cmd_logs.ml` — lines 61, 84–85

```ocaml
Sys.command (Printf.sprintf "kubectl get deployment %s -n %s >/dev/null 2>&1" k8s_name ns)
...
let cmd = Printf.sprintf "kubectl logs -n %s deployment/%s%s%s"
  ns k8s_name follow_flag tail_flag in
```

`k8s_name` and `ns` are not quoted. `k8s_name` is derived from a user-supplied CLI
argument via `resolve_service`.

### `cli/sun/bin/cmd_up.ml` — lines 129–130, 215–220

```ocaml
(* wait_for_rollout *)
Printf.sprintf "kubectl rollout status deployment/%s -n %s --timeout=60s" name namespace

(* docker build/push *)
let docker_cmd = Printf.sprintf "docker build -t %s -f %s %s"
  push_image dockerfile repo_root in
...
Printf.sprintf "docker push %s" push_image
```

`name`, `namespace`, `push_image`, `dockerfile`, and `repo_root` are not quoted.
`push_image` is derived from the `--registry` CLI flag.

## Reference — correct pattern (already used in codebase)

```ocaml
(* cmd_up.ml lines 66-67 — do this everywhere *)
(Filename.quote namespace)
(Filename.quote service)
```

```ocaml
(* sun_cli_manifest.ml line 629 *)
Sys.command (f "kubectl apply -f %s" (Filename.quote tmp))
```

## Remediation

Wrap every interpolated identifier with `Filename.quote` in the three affected files.
Apply the fix to:

1. `cmd_rollback.ml` — `k8s_name` and `ns` in both `undo_cmd` and `status_cmd`.
2. `cmd_logs.ml` — `k8s_name` and `ns` in both `deployment_exists` and the `kubectl logs`
   command.
3. `cmd_up.ml` — `name` and `namespace` in `wait_for_rollout`; `push_image`,
   `dockerfile`, and `repo_root` in the docker build/push commands.

Note: `Filename.quote` in OCaml wraps the argument in single quotes with internal
single-quote escaping, which is correct for POSIX shell. This is already used correctly
elsewhere in the codebase.

## Acceptance criteria

- All `kubectl` and `docker` commands in the affected files use `Filename.quote` for
  every variable interpolated into the shell string.
- A workspace named with shell metacharacters (e.g. `"audit-$(id)_acme"`) does not
  cause unexpected command execution when `sun rollback` or `sun logs` runs.
- Existing tests continue to pass.
