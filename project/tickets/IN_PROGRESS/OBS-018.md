Implement sun status domain/service scope per the design doc; make reachability checks target-aware

**Depends on:** None.

## Problem

Two gaps in `sun status`, found by engineer review:

1. `docs/architecture/observability-design.md` documents `sun status
   payments` and `sun status payments/charge-svc` with a specific output
   shape (domain: services list + rolled-up health + Observability +
   real `sun open ...` `Open` hints; service: the same, scoped to one
   service). Today `cmd_status.ml`'s domain argument is a single
   positional checked with `List.mem d all_domains` — `sun status
   payments/charge-svc` always fails with "Domain not found" (the `/` is
   never handled), and even bare `sun status payments` still prints the
   pre-OBS-009 raw `kubectl get pods` dump, not the documented structured
   view. OBS-009 deliberately left this path "unchanged" per its own
   ticket scoping — which, per this review, doesn't match what the design
   doc actually promises for scoped `sun status`.
2. OBS-015 made `--target` resolve `observability_backend`/`base_domain`
   for display and for `sun logs`/`sun open`'s Grafana URLs, but `sun
   status`'s Loki/Prometheus reachability checks still always probe
   `http://localhost:3100/ready` and `http://localhost:9090/-/healthy`
   regardless of the resolved backend. A real `self_hosted_durable`
   target reports "unreachable" even when its Grafana/Loki/Prometheus are
   perfectly healthy, because nothing ever points the check at them.

## Goal

`sun status <domain>` and `sun status <domain>/<service>` match the
design doc's documented output shape. Reachability checks are honest about
what they actually verified.

## Acceptance criteria

- `sun status <domain>/<service>` is accepted (reuse `Sun_cli_open`'s
  scope-parsing convention) and prints: the service's rolled-up health,
  an Observability block, and an `Open` block with real `sun open
  logs|metrics|dashboard <domain>/<service>` hints — the design doc's
  service-scope example.
- `sun status <domain>` prints: a `Services` list (one line per service in
  that domain with its own rolled-up health), an Observability block, and
  an `Open` block with `sun open logs|metrics|dashboard <domain>` hints —
  the design doc's domain-scope example.
- Per-service/per-domain health rollup reuses the existing diagnosis
  aggregation (`Sun_cli_status`/`Sun_cli_rollout_diagnosis`) — no new
  diagnosis logic.
- The existing raw `kubectl get pods` dump, rollout-diagnosis text, and
  port-forward hints are preserved as additional detail (don't delete
  working debugging output), scoped correctly: domain scope keeps today's
  domain-wide dump; service scope filters it to just that one service's
  pods.
- Loki/Prometheus reachability checks use an explicit
  `--loki-base-url`/`--prometheus-base-url` when given, or the
  `Local` backend's hardcoded defaults when the resolved backend is
  `Local`; otherwise (a non-`Local` backend with no explicit URL) print
  "not checked" rather than a misleading "unreachable".
- Tests cover: `<domain>/<service>` scope parses and resolves; the
  reachability check prints "not checked" for a non-`Local` target with no
  explicit URL, and still checks normally when `Local` or an explicit URL
  is given.
