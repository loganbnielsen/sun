Fix topic discovery to scan event subdirectories.

**Depends on:** None.

**Problem:** FEAT-021's `discover_topics()` scans `events/*.ml` (top-level only). The
generated workspace puts event contracts in `events/<domain>/<event>.ml`
(e.g. `events/payments/charged.ml`), so topic names are never found and
`sun deploy --emit-plan-to` always serializes `"topics": []`.

**Remediation:**

1. Change `discover_topics` in `sun_cli_deployment_plan.ml` to scan
   `events/**/*.ml` recursively (two levels deep is sufficient for the current
   scaffold convention).
2. Update tests to cover the subdirectory layout used by the scaffold.
3. Verify the dogfood workspace (`events/payments/charged.ml`) now surfaces its
   topic in the plan.

**Acceptance criteria:**

- `sun deploy --emit-plan-to` includes `"sun-payments-charged"` (or the actual
  topic name) for a generated workspace with `events/payments/charged.ml`.
- Top-level `events/*.ml` files continue to be discovered (no regression).
