`sun rollback` silently fails for services using `[infra.rollout]` (Argo Rollouts)

**Description:** `cli/sun/bin/cmd_rollback.ml` unconditionally runs `kubectl rollout undo deployment/<name> -n <namespace>` for every discovered service. When a service has `[infra.rollout]` configured in `sun.toml`, `sun_cli_manifest.ml` emits a `kind: Rollout` resource (Argo Rollouts) at line 375, not a `kind: Deployment`. The `kubectl rollout undo deployment/X` command will fail (resource not found) or produce a misleading error for namespaces that have a `Rollout` but no matching `Deployment`. Neither `cmd_rollback.ml` nor any user-facing documentation warns of this incompatibility. `sun.toml` is not read by the rollback command at all.

**Impact:** During a production incident, an engineer who configured canary or blue-green delivery (a documented, encouraged feature) and then runs `sun rollback` will get a kubectl error with no actionable guidance. The previous service version is not restored. This is a high-severity gap because it breaks the primary safety net (`sun rollback`) for exactly the services that have adopted progressive delivery — the most production-conscious users.

**Remediation:** Two options; implement both for full coverage:

**Option A — Fix (preferred):** In `cmd_rollback.ml`, load `sun.toml` for each discovered service using `Sun_cli_toml.load`. If `progressive_delivery` is `Some _`, use `kubectl argo rollouts undo <k8s_name> -n <ns>` instead of `kubectl rollout undo deployment/<k8s_name> -n <ns>`. This requires the Argo Rollouts kubectl plugin to be installed; add a prerequisite check (as done for terraform in `cmd_cloud.ml`) with a clear install URL.

**Option B — Guard (interim):** Add a pre-flight check at the top of `cmd_rollback.ml` that scans each service's `sun.toml`; if `[infra.rollout]` is present, print an actionable error message and exit 1:
```
error: service payments/charge_svc uses Argo Rollouts — kubectl rollout undo does not apply.
  To roll back, run:  kubectl argo rollouts undo charge-svc -n pluto-payments
  Then wait for:      kubectl argo rollouts status charge-svc -n pluto-payments
```

**Documentation fix (always):** Add a note to README.md §"Shipping a Change" and TUTORIAL.md §"Day-2 operations" documenting the current behavior: "`sun rollback` uses `kubectl rollout undo deployment/...`. Services with `[infra.rollout]` configured must be rolled back via `kubectl argo rollouts undo`."
