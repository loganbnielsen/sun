Scope workspace-root chdir to the observability commands only

**Depends on:** None.

## Problem

OBS-013 fixed root discovery by having `main.ml` `chdir` to the workspace
root globally, before Cmdliner even parses subcommand flags. That's too
broad: it silently changes relative-path resolution for every command, not
just `sun status`/`sun logs`/`sun open`. `sun deploy --emit-to <relative
dir>`, `sun deploy --emit-plan-to <relative dir>`, `sun migrate --dir
<relative dir>`, and `sun cloud tf --var-file <relative path>` all resolve
their path arguments relative to the directory the user actually ran `sun`
from today — after OBS-013, those same relative paths now resolve against
the workspace root instead, a silent behavior change for anyone running
those commands from a subdirectory.

## Goal

Only `sun status`/`sun logs`/`sun open` (the commands OBS-013 was actually
fixing) get workspace-root-relative behavior. Every other command's
relative-path flags keep resolving against the invocation directory,
unchanged.

## Acceptance criteria

- `main.ml` no longer `chdir`s globally before dispatch.
- `cmd_status.ml` and `cmd_logs.ml`'s `workspace_name()` (the first thing
  each command's `run` does, before any `app/`-relative scanning) resolves
  the workspace root via `Sun_cli_workspace.find_root` and `chdir`s there
  itself — `cmd_open.ml` gets this for free via `Cmd_logs.workspace_name`.
- `sun deploy --emit-to`/`--emit-plan-to`, `sun migrate --dir`, and
  `sun cloud tf --var-file` are unaffected: a relative path passed to any
  of them still resolves against the directory `sun` was invoked from, not
  the workspace root, whether invoked from the root or a subdirectory.
- `sun status`/`sun logs`/`sun open` still work correctly from any
  subdirectory inside the workspace (OBS-013's original fix, preserved).
