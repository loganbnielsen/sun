Apply the taxonomy label sanitizer to all five label values, not just release

**Depends on:** None.

## Problem

OBS-014 added `sanitize_label_value` (bounds to 63 chars, fixes up a
trailing non-alphanumeric char) but only applied it to `release`.
`workspace`/`domain`/`service`/`primitive` still render raw. `service`
happens to already be k8s-name-safe in this render path (it's always
`k8s_name_to_string` of a validated name), and `workspace`/`domain` are
indirectly bounded today because `namespace_result` validates their
combined length before render is ever called — but that's an implicit
dependency on validation happening upstream, not a guarantee at the label
render site itself. Per engineer review: use one canonical label-value
function for all taxonomy values instead of relying on a value being safe
by construction from somewhere else.

## Goal

Every taxonomy label value goes through the same sanitizer before
rendering, regardless of whether today's call sites happen to already
produce a safe value.

## Acceptance criteria

- `render_taxonomy_labels` applies `sanitize_label_value` to all five
  values (`workspace`, `domain`, `service`, `primitive`, `release`), not
  just `release`.
- Existing taxonomy-label tests still pass unchanged (today's values are
  all already safe, so sanitizing them is a no-op) plus new tests
  confirming `workspace`/`domain` get bounded/fixed-up the same way
  `release` already does.
