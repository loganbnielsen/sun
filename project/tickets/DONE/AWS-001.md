Add low-cost live AWS smoke tests for `aws-eio`.

**Depends on:** `aws-eio` OPAM-readiness work landing.

## Summary

Before running the full `sun cloud init --aws` dogfood path, prove the extracted
`aws-eio` package against real AWS with calls that create no long-running
infrastructure.

## Remediation

1. Add live tests gated by `AWS_EIO_LIVE=1`; the default test suite must not touch AWS.
2. Start with STS `GetCallerIdentity`.
3. Add an S3 tiny-object round trip against a caller-provided bucket and the
   `sun-live-test/` prefix: `PutObject`, `HeadObject`, `GetObject`, `DeleteObject`.
4. Add a missing-key S3 error-path check.
5. Document the required environment variables and the minimal IAM permissions.

## Acceptance criteria

- `dune runtest` skips the live tests unless `AWS_EIO_LIVE=1` is set.
- STS smoke succeeds with normal AWS credentials.
- S3 smoke writes, reads, verifies, and deletes one tiny object under the configured prefix.
- A known-missing S3 key returns the expected error shape.
- Test cleanup runs on failure.
- The full AWS dogfood ticket `project/tickets/BACKLOG/DOGFOOD-011.md` remains blocked
  until these cheaper tests pass.
