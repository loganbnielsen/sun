Capture deploy run logs under `.sun/runs/<run-id>/`

**Depends on:** None.

## Problem

Build, Terraform, Helm, Docker, and kubectl output is currently ephemeral or
spread across ad-hoc terminal output. A failed deploy needs one local place to
inspect exact command logs without flooding the normal CLI output.

## Goal

Give every deploy-like operation a run ID and write phase logs under
`.sun/runs/<run-id>/`.

## Acceptance criteria

- `sun deploy`, `sun cloud apply`, and `sun cloud destroy` create a run
  directory for noisy subprocess logs.
- Normal command output stays compact: phase name, elapsed time, success/fail.
- On failure, Sun prints the run directory and the last useful lines from the
  failed phase.
- A cleanup/retention story exists for old local runs.
- Tests cover run directory creation, phase log naming, and failure tail output.
