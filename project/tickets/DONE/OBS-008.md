Observability label taxonomy: workspace/env/domain/service/primitive/release

**Depends on:** None.

## Problem

`docs/architecture/observability-design.md` defines `workspace`, `env`,
`domain`, `service`, `primitive`, and `release` as the stable identity labels
every log line, metric, and dashboard link should carry — "Kubernetes
namespaces, pod names, Helm release names... are implementation details."

Today, generated pod templates (`cli/sun/lib/sun_cli_manifest_yaml.ml`) only
set `app: <k8s_name>` (plus whatever `sun.toml`'s `[infra.labels]` adds).
`domain` and `workspace` are only recoverable by string-splitting the
Kubernetes namespace (`<workspace>-<domain>`), and `primitive`/`release`
aren't labels anywhere. Promtail (OBS-004) and Prometheus scrape configs
inherit whatever pod labels exist, so they're just as incomplete downstream.

## Goal

Make the six labels real Kubernetes pod labels, set once at manifest
generation, flowing automatically into Loki (via promtail's existing
`__meta_kubernetes_pod_label_*` relabeling) and Prometheus (via its own
label-based service discovery) without per-service configuration.

## Acceptance criteria

- Generated Deployments/CronJobs/Rollouts (`Sun_cli_manifest`) carry
  `workspace`, `domain`, `service`, `primitive` (`svc`/`worker`/`fn`) labels
  in the pod template, in addition to the existing `app` label (kept for
  backward compatibility with existing service/ingress selectors).
- `release` is set to the deployed image tag/SHA when known.
- `env` is documented as coming from the deployment target (kubeconfig
  context / `sun.toml` target), not a pod label — matches
  `observability-design.md`'s note that `env` isn't a CLI path segment
  either.
- Promtail's relabel config (`platform/infra/base`) promotes these new pod
  labels into Loki stream labels, not just `namespace`/`pod`/`container`/`app`.
- `sun_cli_loki`/`sun_cli_rollout_diagnosis`'s existing label-selector
  queries (`app=<k8s_name>`) keep working unchanged — this is additive, not
  a breaking rename.
- Tests cover the new labels appearing in rendered manifests
  (`test_manifest_render.ml`-style golden tests).
