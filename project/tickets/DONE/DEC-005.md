Decide how hosted custom domains and TLS are provisioned.

**Question:** How are custom domains and TLS provisioned in Sun-hosted mode?

**Context:** The infrastructure modules include DNS and cert-manager pieces for self-hosted clusters, but hosted mode needs a user-facing flow for domain ownership, certificate issuance, renewal, and routing.

**Options:**

1. Sun-managed DNS with delegated zones.
2. Customer-managed DNS with CNAME/TXT verification.
3. Both, with customer-managed DNS as the first path.

**Decision criteria:**

- Fastest path for a startup to expose a service publicly.
- Security and ownership verification.
- Operational reliability of certificate renewal.
- Fit with ingress fields already present in `sun.toml`.

**Acceptance criteria:**

- A written decision defines the first supported domain flow.
- The decision identifies which deployment plan fields are needed.
- Follow-up tickets exist for CLI/API/docs work if needed.

**Decision:**

Sun-hosted should provide an instant Sun-managed default URL for every deployed
HTTP service, then support customer-managed DNS for custom domains.

Sun should not become a general-purpose DNS provider in the first hosted version.
For custom domains, customers keep DNS ownership. Sun provides exact DNS records
to add, verifies ownership, and manages certificate issuance/renewal behind the
hosted ingress layer.

The instant default URL is critical for adoption. A user should be able to deploy
the first app and open a working URL without buying a domain, configuring DNS, or
waiting on certificate setup.

**Implications:**

- Hosted deploy should return a reachable default URL such as
  `<service>-<env>-<workspace>.<sun-hosted-domain>`.
- Custom domains use customer-managed DNS with CNAME/TXT verification.
- Sun manages TLS certificates after ownership is verified.
- Sun-owned DNS can be used for Sun's default hosted domains, but customer DNS is
  not managed by Sun in the first version.
- Deployment plans need enough ingress identity to report host/path routing, but
  custom-domain ownership and verification belong to the hosted control plane.
