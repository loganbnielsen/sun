Add `sun logs` Loki query fallback to Kubernetes logs

**Depends on:** OBS-001.

## Problem

`sun logs <svc>` should not fail uselessly when Loki is down, unreachable,
misconfigured, or timing out. Loki being unhealthy is exactly when users need a
fallback path.

## Goal

Prefer Loki when it works, but fall back to Kubernetes logs at runtime when the
Loki query path fails.

## Acceptance criteria

- `sun logs <svc>` attempts a Loki query when observability is configured.
- Loki query failures, timeouts, auth errors, connection errors, and unhealthy
  Loki pods trigger fallback.
- The fallback prints why Loki was skipped before showing Kubernetes logs.
- Fallback uses `kubectl logs` or the Kubernetes API for matching service pods.
- If matching pods are not running, output includes event excerpts from the
  `sun status` diagnosis path.
- Tests cover Loki success, Loki timeout, Loki HTTP error, and missing pod cases.
