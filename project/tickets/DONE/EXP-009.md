TUTORIAL.md contains stale NodePort reference and manual kubectl port-forward step in Parts 3 and 5.

**Depends on:** None.

**Description:** TUTORIAL.md line 240 says "Sun detects that `charge_svc` exposes a NodePort and prints the port-forward command." Services have been ClusterIP since AUDIT-004. TUTORIAL.md line 279 (Part 5, "Try the API") instructs the engineer to manually run `kubectl port-forward svc/charge-svc -n pluto-payments 8080:80`. In reality, `sun up` starts the port-forward automatically as of EXP-005 (which did land).

**Impact:** An engineer following TUTORIAL.md Part 5 step-by-step will either attempt a duplicate port-forward (failing with "port already in use") or believe manual kubectl is always required. The stale "NodePort" reference directly contradicts the current code behaviour, eroding trust in the documentation.

**Remediation:** In TUTORIAL.md:
1. Part 3 (`sun status` output block, lines 232–240): remove "NodePort" reference; update the sample `sun status` output to show `→  http://localhost:8080  (charge-svc)` (the current format from `cmd_status.ml`); remove the adjacent sentence about NodePort detection.
2. Part 5 (lines 275–280): remove the standalone `kubectl port-forward` command; replace with a note that `sun up` started the port-forward automatically; add a recovery note for if the forward was stopped: "run `sun up` again or `kubectl port-forward svc/charge-svc -n pluto-payments 8080:80`".
