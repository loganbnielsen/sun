`examples/local-demo/bin/demo.ml` still annotates two assertions with "(known issue: BUG-008)"/"(known issue: BUG-009)" — both now resolved as invalid (port-forward shadowing, not real bugs), so the annotations are stale.

**Depends on:** None.

## Problem

FEAT-030 added these annotations while BUG-008/BUG-009 were open and
believed to be real Loki/Tempo bugs. Both were subsequently root-caused as
a local `kubectl port-forward` shadowing the demo's Docker containers on
the same ports — not real bugs, no code fix needed, BUG-009 closed
invalid, BUG-008 narrowed to a much smaller port-conflict-detection
follow-up. The demo's failure-detail strings still name these tickets,
which will mislead a future reader into thinking these assertions have a
known, tracked, unresolved cause.

## Remediation

Remove the `"(known issue: BUG-008)"` / `"(known issue: BUG-009)"` suffixes
from the three affected `check` calls in `demo.ml` (Loki logs assertion,
two Tempo assertions). The assertions themselves stay — they're a real,
valuable regression check — only the stale annotation goes.

## Acceptance criteria

- No reference to `BUG-008`/`BUG-009` remains in `examples/local-demo`.
- `dune build` and a live demo run still pass all 7 assertions.
