`sun cloud init` output includes `kubeconfig_command` but docs provide no instruction to run it

**Description:** `sun cloud init` prints a `kubeconfig_command` output line (e.g. `aws eks update-kubeconfig --region us-east-1 --name acme-prod`) as part of its Terraform outputs, but neither `cli/sun/bin/cmd_cloud.ml` runs this command automatically nor do `README.md` or `docs/guides/TUTORIAL.md` provide explicit instruction to run it before proceeding to `sun deploy`. The text following the `sun cloud init` output block jumps directly to "Install platform components." An engineer who misses the `kubeconfig_command` output line will find `sun deploy`, `sun status`, and `sun migrate` failing because `kubectl` has no cluster context.

**Impact:** The Stage 4 invariant "After the command completes, `sun status` shows a reachable cluster with no manual kubeconfig setup" is not met. The engineer must notice the `kubeconfig_command` output and run it — knowledge not made explicit in the primary documentation path. During a first-time cloud setup, this will cause all subsequent Sun CLI commands to fail with cryptic kubectl errors.

**Remediation:** Two options, do one or both: (A) In `cli/sun/bin/cmd_cloud.ml`, after printing Terraform outputs, detect the `kubeconfig_command` non-sensitive output and run it automatically via `Sys.command`, printing "Configuring kubectl…" before running. (B) In `README.md` §"sun cloud init" and `TUTORIAL.md` Part 8, add an explicit post-`sun cloud init` step: "Run the `kubeconfig_command` printed above to configure kubectl — this is required before `sun deploy` will work."
