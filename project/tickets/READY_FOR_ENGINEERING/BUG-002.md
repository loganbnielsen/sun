Exit non-zero from `sun up` when port-forward fails.

**Depends on:** None.

**Problem:** When the port-forward started by `sun up` fails (e.g. port 8080
already in use), `sun up` still exits 0. The service is deployed and running
in the cluster but unreachable locally. The user sees a success message and
then gets connection-refused errors when they try to use the app.

**Remediation:**

1. After starting port-forwards in `sun up`, check whether each port-forward
   process is still alive after a short delay (e.g. 1s).
2. If any port-forward fails, print the current warning more prominently
   (before the success line, not after) and exit non-zero.
3. Include the `kill $(lsof -ti:<port>)` remediation hint in the error output.
4. Add a test or integration note verifying the exit code behaviour.

**Acceptance criteria:**

- `sun up` exits non-zero if the port-forward for any exposed service fails.
- The error output includes the port number and a remediation hint.
- Cluster deployment itself is not rolled back — only the local port-forward
  failure is reported.
