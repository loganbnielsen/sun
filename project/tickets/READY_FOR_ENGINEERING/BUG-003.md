Loki structured metadata not indexed: trace_id round-trip test fails

**Depends on:** None.

**Description:** `test_live_trace_id_round_trip` in `integrations/observability/obs-eio-loki/test/test_loki.ml:270` fails when Loki is running. The test pushes a log line with a `trace_id` in structured metadata and then queries Loki using `| trace_id="<value>"`. The query returns no results, indicating Loki is not indexing the field.

The likely cause is that the Loki Helm chart deployed by `sun dev up` does not have `structuredMetadataPolicy: allow` (or equivalent) set in its config, so Loki drops structured metadata rather than indexing it.

**Impact:** The observability pre-commit suite fails whenever Loki is running, blocking commits and masking real failures.

**Remediation:**

1. Inspect the Loki Helm values used in `cli/sun/bin/cmd_dev.ml` (`helm_install "loki" ...`).
2. Add `loki.structuredMetadata.enabled: true` (or the correct field name for the chart version in use) to the Helm values.
3. If Loki version predates structured metadata support, upgrade the chart version.
4. Re-run the test to confirm `trace_id` is returned in query results.

**Acceptance criteria:**

- `dune test integrations/observability/obs-eio-loki/test/ --force` passes with Loki running.
- `trace_id survives push and query` returns `[OK]`.
