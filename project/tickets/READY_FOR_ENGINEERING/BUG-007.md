`sun new fn`'s generated `lib/dune` doesn't depend on `sun_fn` — the scaffolded library fails to build out of the box.

**Depends on:** None.

## Problem

`cli/sun/lib/sun_cli_scaffold_templates.ml`'s `fn_lib_dune` template:

```
(library
 (name {{lib}})
 (wrapped false)
 (modules {{Mod}}))
```

has no `(libraries ...)` stanza at all, even though the sibling `fn_lib_ml` template it pairs with references `Fn.Cron`/`Fn.FN` (the `sun_fn` package's public modules). Confirmed live: `sun new fn sample/fn` followed by `dune build` on the generated workspace fails immediately with

```
File "app/sample/fn_fn/lib/fn_fn.ml", line 1, characters 14-16:
1 | let trigger = Fn.Cron "0 * * * *"
                  ^^
Error: Unbound module Fn
```

The sibling `worker_lib_dune` and `svc_lib_dune` templates both correctly list their primitive's library (`kafka_eio_service yojson` and `sun_svc` respectively) — `fn_lib_dune` is the one template missing it. `fn_bin_dune` (the executable) does depend on `sun_fn`, which is presumably why this was never caught: the *executable* links fine standalone in a context where dune's whole-project build already built `sun_fn` for something else, but the *library* target itself (`dune build app/.../fn_fn/lib/`) — and a workspace where nothing else pulls in `sun_fn` first — fails.

## Goal

`sun new fn` produces a workspace that builds cleanly with no manual fixes, matching `sun new worker`/`sun new svc`.

## Remediation

1. Add `(libraries sun_fn)` to `fn_lib_dune` in `cli/sun/lib/sun_cli_scaffold_templates.ml`.
2. Regenerate a `sun new fn` scaffold and confirm `dune build` succeeds from a clean workspace with no other primitive scaffolded alongside it (isolates the bug from the whole-project-build masking effect above).
3. Check whether the scaffold-audit skill's coverage already scaffolds a bare `sun new fn` workspace on its own (not just alongside a `sun new workspace` combo that would mask this) — if not, note that gap so this class of bug doesn't recur silently.

## Acceptance criteria

- `sun new fn <domain>/<name>` followed by `dune build` (in a workspace with no other scaffolded primitive) succeeds with no errors.
- `fn_lib_dune`'s libraries list matches the pattern of `worker_lib_dune`/`svc_lib_dune` (the primitive's own library present).
