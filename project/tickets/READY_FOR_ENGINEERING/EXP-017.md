Document `sun dev run` in user-facing guides

**Depends on:** None.

**Description:** `sun dev run` was implemented (EXP-002) and discovers, builds, and spawns all workspace services as native processes against the k3d dev infra, with multiplexed prefixed output. It appears only as a parenthetical in the README Status table — it is absent from the README Quickstart and TUTORIAL.md entirely.

**Impact:** Engineers following the tutorial skip the fast inner dev loop (native processes, no Docker rebuild) and default to `sun up` for every code change, which requires a full image build cycle.

**Remediation:**
1. Add a "Local iteration with `sun dev run`" subsection to TUTORIAL.md (Part 1 or after Part 3's deploy section): explain what it does, when to use it (rapid code-change iteration without Docker rebuild), and how it differs from `sun up` (native processes vs containerised cluster deploy, same infra via port-forwards).
2. Add `sun dev run` to the README.md Quickstart sequence with a one-line explanation.
