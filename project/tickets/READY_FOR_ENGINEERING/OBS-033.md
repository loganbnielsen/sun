Thanos/Loki S3 retention is a flat 90-day literal, not the configurable/tiered policy the docs imply

**Depends on:** None.

## Problem

`platform/infra/aws/main.tf:282-286,343-347` hardcode a 90-day
`expiration` lifecycle rule on both the Loki and Thanos S3 buckets as bare
literals — there is no `retention_days` (or similar) Terraform variable
anywhere in `platform/infra/aws` or `platform/infra/base`. But
`docs/deployment/observability-backends.md` says "change it if you need
longer retention," which reads as "pass a variable," not "edit the
Terraform source and re-apply."

Separately, the Thanos compactor (`platform/infra/base/main.tf`, `compactor.*`
Helm values around line 633) sets no downsampling-resolution retention flags
(`--retention.resolution-raw`/`-5m`/`-1h`). Without those, Thanos's
downsampled blocks inherit the same flat 90-day bucket-level TTL as raw
blocks — defeating one of Thanos's main value props (cheap long-term
downsampled history alongside shorter raw retention).

## Goal

- Retention is a real, documented Terraform variable (or variables, if raw
  vs. downsampled retention should differ), not a value someone has to find
  and hand-edit in `main.tf`.
- The docs describe how to actually change it.
- Thanos's downsampled resolutions get a retention window distinct from raw
  block retention, so long-term trend queries don't silently lose data at
  the same 90-day cutoff as raw metrics.

## Decision

Keep 90 days as the default everywhere — same as today's hardcoded behavior.
The fix is making it real, documented Terraform variables instead of bare
literals in `main.tf`, not changing the default numbers. Four separate
variables, not a generic "raw + per-resolution" scheme, so scope stays small
and each maps to one concrete lifecycle rule / compactor flag:

```hcl
variable "loki_retention_days"          { default = 90 }
variable "prometheus_raw_retention_days" { default = 90 }
variable "thanos_retention_5m_days"      { default = 90 }
variable "thanos_retention_1h_days"      { default = 90 }
```

`loki_retention_days` drives the Loki S3 bucket's `expiration` lifecycle
rule; `prometheus_raw_retention_days` drives the Thanos/Prometheus S3
bucket's raw-block lifecycle rule; `thanos_retention_5m_days`/
`thanos_retention_1h_days` drive the compactor's
`--retention.resolution-5m`/`-1h` flags. An operator who wants downsampled
data to outlive raw data can already do that by overriding those two
variables once they exist.
