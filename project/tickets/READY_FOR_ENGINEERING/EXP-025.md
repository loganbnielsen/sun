`examples/pluto/` reference workspace is out of sync with current `sun new workspace` scaffold output

**Description:** `examples/pluto/` is a reference workspace in the monorepo. It is structurally incomplete relative to what `sun new workspace pluto` currently generates: missing `dune-project` (workspace won't build), `test/test_schemas.ml`, `test/dune`, `.dockerignore`, `.github/workflows/deploy.yml`, `.github/workflows/sun-ci.yml`, and `db/migrations/0001_notifications.down.sql`. Its `README.md` uses pre-CLI commands (`ensure-broker.sh`, raw `dune exec`) rather than the documented Sun CLI (`sun dev up`, `sun dev run`). The workspace also lacks the `vendor/` symlinks section in its README.

**Impact:** An AI agent (or new engineer) that reads `examples/pluto/` as context for workspace conventions will produce structurally incomplete scaffolding — omitting the schema compatibility test, down migration, CI workflow, and Docker ignore file. It will also suggest manual broker setup commands rather than `sun dev up`. This undermines the Stage 9 invariant that agents can make accurate changes from the generated structure alone.

**Remediation:** Regenerate `examples/pluto/` by running `sun new workspace pluto` in a temporary directory and replacing the `examples/pluto/` contents with the output. Alternatively, add a CI check that runs `sun new workspace` and diffs the generated output against `examples/pluto/` to detect drift automatically. If `examples/venus/` is the actively maintained reference workspace, consider removing `examples/pluto/` and updating repo-level references accordingly.
