Correct the env-label promise in the observability design doc; fix stale sun.dev/workspace reference

**Depends on:** None.

## Problem

`docs/architecture/observability-design.md`'s Identity table lists `env` as
one of the labels "every log line, metric, trace, deploy event, and
generated dashboard link must carry," sourced from "which target the CLI is
currently pointed at." OBS-008 shipped the other five taxonomy labels
(`workspace`/`domain`/`service`/`primitive`/`release`) but never emitted
`env` — `sun up`/`sun deploy` have no target-resolution concept at all
today (no `--target`, nothing threaded through
`Sun_cli_deployment_plan`), so there's nothing to source an `env` value
from without inventing a second, disconnected notion of "target" (a flag
like `--env dev`) that would immediately create two sources of truth
against `sun.yml`'s target config. Per engineer review: wiring real
`--target` resolution into `sun up`/`sun deploy` (matching `sun plan`/
`sun cloud tf`'s existing path) is real, separate, deploy-path-touching
work, not a doc fix — so the doc should say what's actually true instead of
describing a contract that silently isn't met.

Separately, `docs/architecture/devops-pipeline.md`'s Generated Kubernetes
Artifact Invariants table still lists `sun.dev/workspace` and
`sun.dev/domain` labels as "Planned," referencing a reverted, unprefixed
implementation attempt (CODEX_STYLE_AUDIT-072) — stale now that OBS-008
shipped bare `workspace`/`domain` labels (no `sun.dev/` prefix, by design,
to match the taxonomy in the observability design doc).

## Goal

Both docs accurately describe what's actually shipped and what's actually
still open.

## Acceptance criteria

- `observability-design.md`'s Identity table (or an inline note) makes
  clear that `env` is not yet emitted, names why (`sun up`/`sun deploy`
  have no target-resolution concept yet), and points at the ticket/future
  work that would add it (via `--target`, not a standalone `--env` flag —
  record that constraint so a future implementer doesn't reintroduce the
  two-sources-of-truth problem).
- `devops-pipeline.md`'s invariants table is updated to reflect the actual
  shipped label names (`workspace`/`domain`, unprefixed) instead of the
  stale reverted `sun.dev/workspace`/`sun.dev/domain` entries, and no
  longer says "Planned" for something that's live (linking to OBS-008).
