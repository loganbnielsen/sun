Scope OBS-011's dashboards to one workspace

**Depends on:** None.

## Problem

`platform/infra/base/dashboards/workspace-overview.json` and
`service-template.json` query by `domain`/`service` labels but never by
`workspace` — `sum(rate(sun_svc_requests_total[5m])) by (domain)` and
`up{domain="$domain"}` have no `workspace` filter at all. If a
`self_hosted_durable` Prometheus/Grafana instance is ever shared across
more than one Sun workspace (a non-default but real possibility for
`self_hosted_durable`, and always true for `external`, where Sun doesn't
provision these dashboards but the underlying label contract is the same),
two workspaces using the same domain name would have their metrics/logs
blended in these dashboards. The `workspace` label exists in the taxonomy
specifically to prevent this — the dashboards don't use it.

## Goal

Both provisioned dashboards are scoped to one workspace, matching the rest
of the label taxonomy's scoping convention (`$domain`/`$service` template
variables already do this at their level).

## Acceptance criteria

- Both dashboards gain a `$workspace` template variable (`label_values(up,
  workspace)`), and every PromQL/LogQL query in both dashboards filters by
  `workspace="$workspace"` in addition to whatever `domain`/`service`
  filters it already has.
- For the single-workspace-per-instance common case (today's documented
  deployment model), the `$workspace` dropdown has exactly one option and
  doesn't add friction — verify this doesn't regress the existing
  workspace-overview/service-template behavior when only one workspace's
  data exists.
