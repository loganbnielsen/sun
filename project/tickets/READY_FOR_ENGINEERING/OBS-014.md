Taxonomy label values are unbounded/unquoted; sun open dashboard skips service-name normalization

**Depends on:** None.

## Problem

Two related correctness gaps found in review of OBS-008/010:

1. `Sun_cli_manifest_yaml.render_taxonomy_labels` (OBS-008) renders all five
   label values unquoted and unbounded. `release` in particular is an
   arbitrary substring of the image tag (`release_of_image`) with no length
   or charset guard — a long CI-generated tag exceeds Kubernetes' 63-char
   label-value limit and makes `kubectl apply` fail outright, and an
   unquoted numeric/boolean-looking tag (e.g. `release: 123`) gets parsed
   as a non-string YAML scalar. This can break real deploys, not just
   dashboards. (`sun.dev/config-hash` already gets quoted for exactly this
   reason — the taxonomy labels don't follow the same convention.)
2. `Sun_cli_open.dashboard_url` (OBS-010) passes a scoped service name
   through to the dashboard URL's `var-service` query param unchanged,
   while `logs_url`'s `Service` branch normalizes it via
   `Sun_cli_deployment_plan.k8s_name_result` first (matching the `service`
   label's actual rendered value, which is always the k8s/hyphenated
   form). `sun open dashboard payments/charge_svc` (underscore form) opens
   a dashboard filtered on a `$service` value that never matches any
   metric's `service` label — the dashboard renders empty.

## Goal

One consistent, bounded, quoted representation for every taxonomy label
value, and consistent k8s-name normalization everywhere a service name
flows into something that gets compared against rendered labels (dashboard
links, log links, and any future consumer).

## Acceptance criteria

- All five taxonomy label values render quoted in the emitted YAML.
- `release_of_image`'s output is bounded to Kubernetes' 63-char label-value
  limit and does not end on a non-alphanumeric character after truncation.
- `Sun_cli_open.dashboard_url`'s `Service` case normalizes the service name
  via the same k8s-name conversion `logs_url` already uses, so
  `sun open dashboard payments/charge_svc` and
  `sun open logs payments/charge_svc` preset the same `service` value.
- Tests cover: a label value that would exceed 63 chars gets truncated
  safely; a numeric-looking release tag renders quoted; `dashboard_url`
  and `logs_url` agree on the normalized service name for the same scope
  input.

## Drive-by (same theme, cheap)

`Sun_cli_logs.url_encode_logql` only encodes `{ } " , = <space>`, leaving
`+ % & ? #` untouched inside a LogQL query embedded as a URL query-param
value. Round out the encoder while touching this file.
