One canonical label-value sanitizer, shared by manifest rendering and sun open's dashboard links

**Depends on:** None.

## Problem

Two related gaps, confirmed by the reviewer's own dry-run: manifest labels
were `workspace: "Sun_Obs_Review_App"` / `domain: "Payments_Team"` while
the corresponding dashboard URL used
`var-workspace=sun-obs-review-app&var-domain=payments-team` — the
dashboard opens empty because the two values never match.

1. `Sun_cli_manifest_yaml.sanitize_label_value` (OBS-014/019) only bounds
   length and fixes the trailing character. It doesn't lowercase, doesn't
   touch underscores, and doesn't fix a leading non-alphanumeric character
   or other invalid internal characters (spaces, etc.) — `My App` as a
   workspace directory name still renders an invalid Kubernetes label.
2. `Sun_cli_open.dashboard_url` normalizes `workspace`/`domain` via
   `Sun_cli_kubernetes_name.normalize` (lowercase + underscore→hyphen
   only) before building `var-workspace`/`var-domain`. That's a
   *different* transform than #1, so for any workspace/domain containing
   uppercase, underscores, or other non-hyphen characters, the rendered
   label and the dashboard link's query param permanently disagree.

## Goal

One function, used by both call sites, so a manifest's `workspace`/
`domain`/`service`/`primitive`/`release` labels and `sun open`'s
`var-workspace`/`var-domain` always agree for the same input — and that
function actually guarantees a valid Kubernetes label value, not just a
bounded one.

## Acceptance criteria

- A single `sanitize_label_value` (in `Sun_cli_kubernetes_name`, alongside
  the existing `normalize`) lowercases, replaces every character that
  isn't alphanumeric or `-` with `-` (a superset of `normalize`'s
  underscore-only handling), bounds to 63 chars, strips leading
  non-alphanumeric characters entirely (not just fixing one), and fixes a
  trailing non-alphanumeric character the same way today's version does.
- `Sun_cli_manifest_yaml.render_taxonomy_labels` and
  `Sun_cli_open.dashboard_url` both call this one function for
  `workspace`/`domain` (service/primitive/release keep going through it
  too, per OBS-019's "uniform" requirement — they're already safe by
  construction, so this is a no-op for them).
- `Sun_cli_manifest.sanitize_label_value` (the existing public re-export
  used by tests) keeps working, now delegating to the shared
  implementation.
- Tests confirm: a workspace/domain value that's mixed-case with
  underscores renders identically as a manifest label and as a `sun open`
  dashboard URL's query param for the same input; a value with an internal
  space, and one with a leading non-alphanumeric character, both sanitize
  to a valid Kubernetes label value.
