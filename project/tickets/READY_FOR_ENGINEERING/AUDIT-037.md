# AUDIT-037 — Dockerfile template missing `otoml` and `ptime` from opam install

**Depends on:** None.

## Description

The `tpl_dockerfile` template in `cli/sun/lib/sun_cli_cmd_new.ml` (lines 430–433) is missing `otoml` and `ptime` from its `opam install` step. Both packages are required to compile the vendored Sun framework source inside the container:

- `ptime` is a direct dependency of `kafka-eio-service/lib/kafka_service.ml`, used in `tls_authenticator` to compute certificate validity time via `Ptime.of_float_s`.
- `otoml` is a dependency of `cli/sun/lib/sun_cli_toml.ml`, which is transitively linked by `sun-svc`, `sun-worker`, and `sun-fn`.

Any Docker build of a scaffolded workspace will fail when `dune build` runs inside the container with `Error: Library "ptime" not found` or `Error: Library "otoml" not found`.

## Impact

Every workspace generated by `sun new workspace` produces Docker images that fail to build without manually editing the Dockerfile. This breaks the zero-knowledge onboarding guarantee.

## Remediation

In `cli/sun/lib/sun_cli_cmd_new.ml`, update the `tpl_dockerfile` `opam install` step:

```
RUN opam install -y --no-self-upgrade \
    eio eio_main cohttp-eio yojson cmdliner base64 uri cstruct mtime \
    tls-eio x509 domain-name ptime otoml \
    caqti-eio caqti-driver-postgresql
```

Add `ptime` and `otoml` between `domain-name` and `caqti-eio`.
