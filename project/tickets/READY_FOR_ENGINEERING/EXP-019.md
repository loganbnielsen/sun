TUTORIAL Part 8 bypasses `sun cloud init`; all `sun cloud` subcommands missing from CLI reference tables

**Description:** TUTORIAL.md Part 8 ("Production deployment") shows raw `terraform init` + `terraform apply` commands for AWS and GCP provisioning, bypassing `sun cloud init` entirely. `sun cloud init` is implemented (`cli/sun/bin/cmd_cloud.ml`) and documented in `README.md` (§"Cloud Infrastructure — `sun cloud init`") but never mentioned in the tutorial. Neither the TUTORIAL.md CLI reference table (lines 459–485) nor the README.md CLI reference table lists any `sun cloud` subcommands (`init`, `deploy`, `releases`, `logs`).

**Impact:** An engineer following the tutorial is directed to run Terraform manually rather than using the Sun CLI. This breaks the "without consulting external documentation" promise for Stage 4: the engineer needs Terraform knowledge, cloud-provider CLIs, and knowledge of where the Terraform modules live — all of which `sun cloud init` abstracts away. The four `sun cloud` subcommands are invisible from both primary reference surfaces.

**Remediation:**
1. Update TUTORIAL.md Part 8 ("Provisioning a production cluster") to show `sun cloud init --aws` / `sun cloud init --gcp` as the primary provisioning command. The current Terraform section can be retained as an "Advanced / manual override" note for engineers who need full Terraform control.
2. Add the following to both the TUTORIAL.md CLI reference table and the README.md CLI reference table:
   ```
   sun cloud init --aws|--gcp [--var-file FILE] [--dry-run]   provision cloud infrastructure via Terraform
   sun cloud deploy [--environment ENV] [--registry URL]       build, push, and record a hosted release
   sun cloud releases [--page N]                               list recent hosted releases
   sun cloud logs --release ID                                 stream deploy log for a release
   ```
