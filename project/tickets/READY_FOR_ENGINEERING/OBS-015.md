sun status/logs/open should read observability_backend/base_domain from --target, not just flags

**Depends on:** OBS-013.

## Problem

OBS-012's `Sun_cli_observability_url.resolve` is backend-aware in name only
— it never reads any config. `sun status`/`sun logs`/`sun open` default
`--observability-backend` to the literal string `"local"` and
`--base-domain` to nothing, with no path to the actual deployed target's
configuration. `sun.yml`'s target schema (`Sun_cli_config`, used by
`sun plan`/`sun cloud tf`) already carries `base_domain` per target — a real
`self_hosted_durable` deployment on, say,
`sun/prod/aws/us-east-1.yml` looks unreachable/wrong by default unless the
user remembers to pass `--observability-backend self_hosted_durable
--base-domain ...` on every invocation.

Per engineer review: wire `sun status`/`sun logs`/`sun open` into the same
target-resolution path `sun plan`/`sun cloud tf` already use
(`Sun_cli_config.load_for_target`), rather than adding a second,
disconnected notion of "target." `sun up`/`sun deploy` are explicitly
**out of scope** here — they have no target-resolution concept at all today
and wiring one in is a larger, separate piece of work (see OBS-016's doc
note on the `env` label).

## Goal

`sun status`/`sun logs`/`sun open` gain an optional `--target
<env>/<provider>/<region>` flag. When given, load config via
`Sun_cli_config.load_for_target` and use the target's `observability_backend`
and `base_domain` as the resolved defaults. Explicit
`--observability-backend`/`--base-domain`/`--grafana-base-url` flags still
win when passed (layering: explicit flag > `--target` config > hardcoded
`"local"` default) — this is additive, not a breaking change for today's
flag-only usage.

## Acceptance criteria

- `Sun_cli_config.target` gains an `observability_backend : string option`
  field, parsed from the `target:` section the same way `base_domain`
  already is (optional key, absent means "not set").
- `sun status`/`sun logs`/`sun open` accept `--target <path>`. When given
  and it fails to load or resolve, print a clear error (matching
  `sun plan`'s existing error handling) rather than silently falling back.
- When `--target` is given and no explicit `--observability-backend`/
  `--base-domain` override is passed, the resolved backend/base_domain come
  from that target's config.
- When `--target` is omitted, behavior is unchanged from today (flag
  default `"local"`, no base_domain).
- Tests cover: target with `observability_backend` set is used; target
  without it set falls back to `"local"`; an explicit flag overrides the
  target's value; an invalid `--target` path/value errors clearly.
