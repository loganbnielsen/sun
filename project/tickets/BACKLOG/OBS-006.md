Durable log storage (self_managed_durable profile)

**Depends on:** OBS-005.

## Problem

OBS-005 defines an `observability_backend = "self_managed_durable"` profile
but leaves its implementation as a placeholder. For logs, that means
object-storage-backed Loki: chunks and index data in S3/GCS instead of local
disk, so log history survives pod rescheduling and cluster teardown/recreate.

## Goal

Implement the `self_managed_durable` profile for logs.

## Acceptance criteria

- When `observability_backend = "self_managed_durable"`, Loki's chunk and
  index storage is object-storage-backed (S3 on `platform/infra/aws`) instead
  of local PVC. GCP/GCS is explicitly deferred — not required by this ticket;
  leave a TODO rather than stub in unverified wiring.
- Loki configuration follows Grafana's documented recommended architecture for
  object-storage-backed deployments (chunks + TSDB/boltdb-shipper index both
  in object storage).
- Required IAM/credentials (bucket access) are provisioned by the same
  Terraform module, consistent with how `platform/infra/aws` already
  provisions IRSA for cert-manager.
- `sun logs <svc>` continues to work unchanged against this profile — no
  service-code or CLI changes required, only infra.
- Teardown behavior is explicit: destroying the cluster does not delete the
  object storage bucket/retained logs unless the target config says to.
- Documented: what this profile costs to run (compute + storage) and what it
  requires from the user's cloud account.
- **Verification:** `dune build`/`terraform validate` only — no live
  cluster/AWS smoke test in this pass.
