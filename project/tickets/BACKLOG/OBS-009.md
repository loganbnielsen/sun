`sun status` workspace-level index

**Depends on:** OBS-010.

## Problem

`sun status` (`cli/sun/bin/cmd_status.ml`) already shows per-domain pod
tables plus Kubernetes rollout diagnosis (OBS-001) when given a domain, but
there's no single top-level view of the whole workspace —
`docs/architecture/observability-design.md`'s "one dashboard, whole
workspace" goal has no CLI equivalent for a quick health check across every
domain.

Waits on OBS-010 so the index's `Open` hints (`sun open logs`, `sun open
metrics`, `sun open dashboard`) point at commands that actually exist,
matching the design doc's example output, instead of being written and
then silently going stale.

## Goal

Running `sun status` with no arguments shows a workspace index: every
domain's rollout health at a glance, plus the active observability backend
and its own health.

## Acceptance criteria

- `sun status` (no args) prints one line per domain: name and a rolled-up
  status (`healthy` / `degraded` / `not deployed`), derived from the same
  per-service diagnosis OBS-001 already computes — no new diagnosis logic,
  just aggregation.
- The index also shows the active `observability_backend` (`local` /
  `self_hosted_durable` / `external`) and whether Loki/Prometheus themselves
  are reachable.
- The `Open` section prints real `sun open logs`/`sun open metrics`/
  `sun open dashboard` command hints (OBS-010), not placeholder text.
- `sun status <domain>` keeps today's existing detailed per-domain output
  unchanged — this is additive at the no-argument case, not a behavior
  change for existing usage.
- Degraded/not-deployed domains are visually distinguishable from healthy
  ones in the default (non-`--json`) output.
- Tests cover the aggregation logic (all healthy / one degraded / one not
  deployed) independent of any live cluster.
