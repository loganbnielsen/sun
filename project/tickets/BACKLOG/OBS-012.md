Backend-aware observability URL resolution

**Depends on:** OBS-005.

## Problem

`Sun_cli_logs.grafana_explore_url` and `sun logs`'s `--grafana-base-url`
flag hardcode a single flat base URL (default `http://localhost:3000`).
That's fine for `local`, but OBS-005 already added `self_hosted_durable`
and `external` backend profiles — each implies a different place Grafana
(or a completely different vendor UI) actually lives:

- `local` — port-forwarded/dev, `http://localhost:3000`.
- `self_hosted_durable` — Grafana is real, in-cluster, exposed via the
  `grafana.${base_domain}` Ingress `platform/infra/base/main.tf` already
  creates. `sun open`/`sun logs` should resolve to that real URL, not
  `localhost`.
- `external` — Sun doesn't know the vendor's dashboard URL shape at all
  (Grafana Cloud, Datadog, whatever the user pointed `external_loki_url` at
  are all different products). There's nothing safe to link to.

`sun open` (OBS-010) needs one shared answer to "what's the base
observability UI URL for this target" instead of every command inventing
its own flag and default.

## Goal

One resolver, one source of truth, used by `sun logs`, `sun open`, and
`sun status`'s `Open` hints alike.

## Acceptance criteria

- A single function/module resolves the base observability UI URL (or "no
  URL available") from the active `observability_backend` plus whatever
  config that profile already carries (`base_domain` for
  `self_hosted_durable`).
- `local` keeps today's `http://localhost:3000` default, still
  overridable by flag for non-standard port-forward setups.
- `self_hosted_durable` resolves to `https://grafana.<base_domain>`
  matching the existing Ingress, with no extra configuration required
  beyond what OBS-005 already collects.
- `external` returns an explicit "no generated URL for this backend" result
  rather than guessing — callers (`sun open`, `sun logs`) print a short note
  pointing the user at their configured provider instead of a broken link.
- `sun logs`'s existing `--grafana-base-url` flag keeps working as an
  override on top of the resolver, not removed.
- Leaves an explicit extension point (documented, not implemented) for a
  future Sun-hosted UI to plug in as a fourth resolvable target without
  changing this interface.
- Tests cover all three backend profiles' resolution, including the
  `external` no-URL case.
