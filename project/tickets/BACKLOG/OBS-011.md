Provision Grafana dashboards (workspace/domain/service scope)

**Depends on:** OBS-008.

## Problem

Grafana ships in `platform/infra/base` with no dashboards provisioned at
all — a user gets an empty Grafana and has to hand-build every panel.
`docs/architecture/observability-design.md` calls for a workspace overview,
domain overview, per-service dashboard, service logs view, and (when
available) a deploy/release timeline, all filtering by Sun's label taxonomy
rather than namespace/pod names.

This is also the least concretely specified part of the design doc —
expect to make real layout/panel decisions in this ticket, not just wire up
something already fully speced.

## Goal

Sun provisions a baseline set of Grafana dashboards automatically, filtered
by the OBS-008 label taxonomy, so a fresh cluster has something useful to
look at without hand-building panels.

## Acceptance criteria

- Dashboards are provisioned via Grafana's sidecar ConfigMap-loading
  mechanism (`grafana.sidecar.dashboards`, already available in the
  `loki-stack` chart Sun uses) rather than manual import.
- At minimum: one workspace-overview dashboard (all domains' request
  rate/error rate/pod health) and one per-domain dashboard template
  parameterized by the `domain` label from OBS-008.
- Dashboards query Loki/Prometheus using the OBS-008 labels
  (`workspace`/`domain`/`service`/`primitive`), not raw namespace/pod
  names.
- Documented: what's provisioned by default vs. what a user is expected to
  build themselves (service logs view and deploy/release timeline may be
  deferred — say so explicitly rather than silently omitting them).
- Verified against a real Grafana instance that the provisioned dashboards
  actually render (a JSON dashboard definition that Grafana rejects at load
  time is worse than none) — this one needs at least a local `sun dev up`
  check, unlike the AWS-only tickets earlier which stayed at static
  validation.
